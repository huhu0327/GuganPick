# 구조

## 구성 요소

| 구성 요소 | 역할 | 의존 방향 |
|---|---|---|
| Chrome 확장 런타임 | 아이콘 클릭, 페이지별 스크립트 실행, 로컬 상태 보관, 탭 열기 | `manifest.json`에 등록된 서비스 워커와 콘텐츠 스크립트를 호출한다. |
| 공용 로직 | SOOP URL·시간 범위 검증, 표시 시간 변환, 항목 키 생성 | 브라우저 API에 의존하지 않으며 서비스 워커·콘텐츠 스크립트·Node 검사가 함께 사용한다. |
| 백그라운드 서비스 워커 | 아이콘 클릭을 현재 탭에 전달하고 선택한 SOOP 주소를 새 탭 또는 현재 탭에서 연다 | 공용 URL 검증을 통과한 요청만 Chrome 탭 API로 전달한다. |
| 카페 콘텐츠 스크립트 | 현재 문서 프레임의 본문·현재 댓글에서 링크와 구간을 수집하고 패널을 표시한다 | 카페 DOM을 읽어 공용 로직으로 검증한 뒤 로컬 저장소에 항목 목록을 기록한다. |
| SOOP 콘텐츠 스크립트 | 저장된 항목을 불러와 본편을 찾고 시작 위치와 종료 동작을 제어한다 | SOOP DOM의 광고·본편 미디어와 Chrome 로컬 저장소에 의존한다. |
| 네이버 카페 | 영상 제보가 존재하는 외부 입력 경계 | DOM 텍스트, 링크, 링크 카드, iframe 주소만 확장으로 들어온다. |
| SOOP | 원본 영상을 재생하는 외부 실행 경계 | 허용된 플레이어 URL과 실제 미디어 상태만 확장이 사용한다. |

프로젝트는 별도 서버나 데이터베이스가 없는 단일 확장 모듈이다. 카페와 SOOP 페이지는 서로 직접 상태를 전달하지 않고 `chrome.storage.local`의 항목 목록과 활성 번호를 통해 이어진다.

## 대표 흐름

1. 사용자가 네이버 카페 게시글에서 확장 아이콘을 누르면 서비스 워커가 패널 열기 메시지를 콘텐츠 스크립트에 보낸다.
2. 콘텐츠 스크립트는 선택된 범위의 링크 속성·링크 카드 데이터·iframe 주소·텍스트 노드에서 후보 URL을 찾는다.
3. 공용 로직이 후보를 검증하고 시간 정보를 내부 항목으로 변환한다.
4. 중복 항목을 정리한 목록과 활성 번호를 로컬 저장소에 쓴다.
5. 카페 패널에서 사용자가 항목을 누르면 서비스 워커가 SOOP 탭을 열거나 현재 SOOP 탭을 해당 주소로 이동한다.
6. SOOP 콘텐츠 스크립트는 저장된 항목을 읽어 패널을 표시한다. 탭이 열린 것만으로 재생하지 않으며, 사용자가 SOOP 패널에서 해당 항목의 재생을 다시 눌러야 한다.
7. 재생 요청 뒤 광고가 재생 중이면 기다리고, 본편 미디어가 준비되면 시작점으로 이동해 재생하면서 상태를 로컬 저장소에 반영한다.

## 경계

카페 경계에서는 DOM의 속성과 텍스트가 추출 단계로 들어오고, 검증·변환된 항목만 로컬 저장소 경계를 지난다. SOOP 경계로는 플레이어 URL과 본편 미디어의 재생 위치가 전달되며, SOOP에서 읽은 미디어 상태는 다시 로컬 항목 상태로 돌아온다.
