# 개발 기준

## 의존성과 실행 형태

- 런타임 외부 패키지와 빌드 단계를 추가하지 않는다. 위반 기준은 압축해제 확장으로 원본 파일을 직접 로드할 수 없게 되는 변경이다.
- 브라우저 기본 기능과 Chrome 확장 API로 해결할 수 없는 요구가 확인된 경우에만 새 의존성을 검토하며, 추가 전 사용자 승인을 받는다.

## 모듈 경계

- URL·시간·중복 판별처럼 페이지 DOM과 무관한 규칙은 `core.js`에 둔다. `core.js`가 `chrome`, `document`, `window`에 의존하면 위반이다.
- 카페 DOM 수집과 SOOP 미디어 제어는 `content.js`, 아이콘·탭 중계는 `background.js`가 소유한다. 서비스 워커가 페이지 DOM을 읽거나 콘텐츠 스크립트가 검증되지 않은 주소로 탭을 열면 위반이다.
- `core.js`는 전역 API와 CommonJS 내보내기를 모두 유지한다. 서비스 워커, 콘텐츠 스크립트, Node 검사 중 하나에서 로드되지 않으면 위반이다.

## 입력과 출력

- URL 허용 여부는 정확한 호스트 집합과 플레이어 경로를 함께 검사한다. 부분 문자열 호스트 검사 또는 임의 경로 허용은 금지한다.
- 페이지에서 읽은 문자열은 `textContent` 또는 속성값으로 처리하고, 목록 표시는 `textContent`로 만든다. `innerHTML`, `eval`, 동적 스크립트 삽입으로 입력을 실행하면 위반이다.
- 새로운 상태는 직렬화 가능한 값만 `chrome.storage.local`에 저장한다. DOM 노드, 함수, 미디어 객체를 저장하면 위반이다.

## 검증 기준

- `core.js`의 분기·파서·키 규칙을 바꾸면 정상, 경계, 거부 사례를 `test_core.js`에 한 개 이상 추가하고 `node .\test_core.js`를 통과시킨다.
- `content.js`, `background.js`, `manifest.json`을 바꾸면 확장을 다시 로드한 뒤 카페 패널 열기와 SOOP 탭 재생 흐름을 직접 확인한다. Node 검사만으로 브라우저 통합을 통과했다고 표시해서는 안 된다.
- 호스트 권한을 넓히거나 외부 통신을 추가하는 변경은 보안 정책 변경이므로 구현 전에 사용자 승인을 받아야 한다.
